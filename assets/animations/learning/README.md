## Reverse accumulation: assumptions and explanation

The two updates are $x_{n+1}=S_n(x_n,\theta)$, with a fixed initial state and
terminal scalar loss $L=\ell(x_2)$. Each update map is assumed differentiable.
The animation uses $x,\theta,L$ for the book's $z,p,J$; the roles are identical.
The reverse seed is $\lambda_2=\nabla_{x_2}L$. Each preceding adjoint is obtained
by the transposed state Jacobian. A scalar parameter or parameter vector used
twice contributes through both update maps:

$$
\frac{dL}{d\theta}=B_0^T\lambda_1+B_1^T\lambda_2,
\qquad B_n=\frac{\partial x_{n+1}}{\partial\theta}.
$$

The complete equality is displayed together before its two contributions are
highlighted.
For a parameter-dependent initial state or loss, add the corresponding
initial-state and direct-loss terms, as derived in book §5a. An optimiser uses
the gradient to choose a parameter update. Crack initiation, branching,
history maxima and active-set changes require analysis of the relevant
smoothness assumptions and derivative choices.

**Pause and ask:** What term would be missing if only the final use of the
shared parameter were differentiated? **Answer:** $B_0^T\lambda_1$.

## Checked proposals: assumptions and explanation

Radius GNO and GNN are alternative architecture choices. Define feature channels, graph or mesh convention,
node order, units and normalisation, then require the architecture and saved
model to match the contract. A damage candidate must satisfy the declared
admissibility and residual/constraint tests. Bounds and irreversibility express
admissibility; equilibrium and physical interpretation require the appropriate
residuals, balance laws and model assumptions.

The first decision accepts a passing candidate or requests a reference
correction. The corrected candidate is checked again. A second failure stops
the calculation and reports nonconvergence. The chosen tolerances, boundary
conditions and constrained residual must be specified for the actual problem.
The displayed control flow explains how a compatible model proposal enters
this assessment and correction procedure.

**Pause and ask:** Which costs belong in a runtime comparison?
**Answer:** Measure the complete route, including prediction, conversion,
checks, correction and any fallback, alongside field quality and failure rates.

## Rebuild

```bash

  --media_dir .build/animations/learning --disable_caching \
  --verbosity WARNING --progress_bar none \
```
